Open **Maintenance** with **Alt+M** and run WinUtil as administrator. The left panel contains the Scheduled Task switches, report button, Windows Update switch, Task Scheduler viewer, and **WinGet - Reinstall**. The right panel contains **Legacy Windows Panels**, with its heading and shortcut buttons centered inside the panel. The required maintenance files are embedded in WinUtil and deployed to `C:\IT-MAINTENANCE`; copying a folder or pasting code into PowerShell/ISE is no longer required.

The original `Task Scheduler.bat`, `CLEANER.bat`, `GET-INFOMATION.txt`, and `IT-MAINTENANCE.txt` are preserved byte-for-byte. Files being replaced are backed up under `C:\IT-MAINTENANCE\Backup`. The destination refuses junctions/symbolic links and is protected so only Administrators and SYSTEM can modify the installed scripts. Setup is not transactional; inspect the WinUtil session log if an action fails.

## 1. Shutdown and cleanup tasks

Turn the switch **on** to create or replace the same two daily tasks as the original batch file, then check that both tasks exist and are enabled:

| Task | Local time | Action |
| --- | --- | --- |
| `IT-SHUTDOWN` | 21:30 daily | Starts `shutdown.exe -s -t 600`, giving a ten-minute countdown before shutdown around 21:40. |
| `IT-CLEAN` | 12:30 daily | Runs the original `C:\IT-MAINTENANCE\CLEANER.bat`. |

The original highest-privilege/current-account task context is retained. Reinstalling uses `/F` to replace these two named tasks. Turning the switch **off** stops a running scheduled instance when applicable and deletes both task definitions. It keeps the installed files and reports. A shutdown countdown already started by Windows is not cancelled. Turning the switch on does not run the cleaner or shut down Windows immediately.

Task creation and verification run in the background. The switch updates before the completion dialog appears; dismiss that dialog to continue using WinUtil. The Task Scheduler viewer remains available while maintenance is running.

:::caution
The original cleaner stops the print spooler, clears queued print files, and deletes matching temporary, `.log`, `.old` and other files across the system drive, as well as Windows Temp/Prefetch and recent-item files. Its original behavior is retained; it is not restricted to old Temp files. Review the confirmation before scheduling it.
:::

## 2. Export software and DxDiag now

This action runs the original **GET-INFOMATION** code in Windows PowerShell and verifies two newly written reports:

- `C:\IT-MAINTENANCE\<computer>.csv`: Windows, Microsoft Office, and installed software, with columns `PhanMem`, `PhienBan`, `NhaPhatHanh`, `NgayCaiDat`, and `LicenseStatus`.
- `C:\IT-MAINTENANCE\<computer>.txt`: the DxDiag computer report.

The software list reads machine registry entries and the current elevated account's entries, matching the original script. Reports with the same names are overwritten. No account configuration, employee login, scheduled inventory task, or restart is required. Completion is reported only after both fresh reports exist, DxDiag has finished writing, and the CSV has the expected columns.

## 3. C:/D: disk monitoring

Turn the switch **on** to run the original **IT-MAINTENANCE** installer in Windows PowerShell without its closing console pauses, then verify the generated script, `VolumeInfo.json`, and task. There is no need to open PowerShell ISE. D: must be available during installation.

The original `IT-MAINTENANCE` task runs as SYSTEM at **09:00 and 14:00, Monday-Friday**:

- C: receives free-space warnings and is never hidden.
- D: receives warnings at 20–30 GB free.
- Below 20 GB, the original script warns and waits **60 minutes**. If it remains below 20 GB, it removes the D: drive letter. The data is not deleted. The original script restores the letter when the tracked volume reaches at least 20 GB free and D: is available.
- When both C: and D: have more than 30 GB free, the original script runs `chkdsk /scan` and then `defrag /O` where the scan succeeds.

The installer creates the schedule; it does not start a disk scan immediately. Turning the switch **off** stops a running scheduled instance and deletes the `IT-MAINTENANCE` task while retaining the installed script, `VolumeInfo.json`, logs, and reports. Inspect **Task Scheduler → IT-MAINTENANCE** and `C:\IT-MAINTENANCE\DiskMonitor.log` afterward. Automatic D: hiding/restoration is part of the original behavior and is stated in the confirmation.

## Windows Update

Use the **Windows Update** switch:

- **On** restores Windows Update defaults.
- **Off** asks for confirmation, then disables updates. Canceling restores the switch to the actual state.

Opening Maintenance only reads the current update state. Restart Windows after changing the switch. See the [Windows Update guide](/guides/updates/) for details.

## WinGet and Windows panels

**WinGet - Reinstall** runs the existing WinGet repair workflow. **Legacy Windows Panels** opens Computer Management, Control Panel, Mouse Properties, Network Connections, Power Options, Printers, Programs and Features, Region, Security and Maintenance, Sound, System Properties, Time and Date, Windows Defender Firewall, and Windows Restore.

These tools moved from Config to Maintenance. The Config tab, optional Windows Features controls, other Fixes, CTT PowerShell Profile installation/removal, and Remote Access setup have been removed. Existing Windows features, profiles, and SSH installations are not changed by this UI update. The unused two-phase account/setup workflow and alternative maintenance workers have also been removed from the source; existing installed files and scheduled tasks are retained.
